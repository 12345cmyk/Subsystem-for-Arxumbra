# ArxUmbra v8 — 16K UASTC фон + меню F1 (генеративная текстура + анимации) + PGO/BOLT CI

v8 = v7 + пять улучшений:

1. **Сгенерированная текстура бокового меню** — `assets/menu.ktx2`: чистая
   градиентная панель без элементов (тёмный индиго → глубокий графит),
   неоновая кромка справа, альфа-затухание к правому краю. UASTC 4x4 sRGB,
   768×2048, **полная мип-цепочка (12 уровней)** — на 16K мониторах панель
   рендерится практически 1:1 к текселю, на меньших разрешениях мипы дают
   чистый даунскейл без мерцания. 782 865 байт (zstd-суперкомпрессия).
2. **F11 → F1** — переключение меню перенесено на F1 (F11 занят браузерами).
3. **Плавные анимации** открытия и закрытия: 250 мс, smoothstep-кривая
   (p²·(3−2p)) — панель выезжает слева с лёгким выносом (1.05× ширины) и
   одновременно проявляется по альфе; неоновые полосы едут вместе с панелью.
   Повторное F1 в середине анимации **разворачивает её в обратную сторону**.
4. **Чистый код**: из `src/main.rs`, `Cargo.toml` и `.cargo/config.toml`
   удалены все комментарии — экстремально кристально и линейно.
5. **CI исправлен**: в Linux-job добавлены `libwayland-dev libxkbcommon-dev
   pkg-config` (без них build-скрипт wayland-sys не находит wayland-client
   через pkg-config — единственный красный шаг в реальном прогоне v7).
   Тренировочные прогоны теперь **сами нажимают F1** (ButtonInput::press из
   патча) — PGO/BOLT профили покрывают декод меню, анимации и рендер панели,
   а не только фон.

Плюс: бинарь в архиве упакован в xz (в zip не влезал: сырое дерево + активы +
бинарь = 131.7 МБ > лимита 128 МБ).

## 0. Быстрый старт

В архиве — готовый Linux-бинарь (упакован в xz) и полный репозиторий
с исходниками:

```
unzip arxumbra-v8.zip && cd arxumbra-v8
xz -d linux-subsystem-for-arxumbra.xz     # права +x сохранятся
./linux-subsystem-for-arxumbra            # Wayland-сессия, GPU с BC7/ASTC
F1 — открыть/закрыть меню                  # Esc (удержание 7 c) — выход
```

Бинари macOS/Windows собирает CI из этого же репозитория (раздел 3):
`linux-subsystem-for-arxumbra-{macos-aarch64.tar.gz, windows-x86_64.exe}`
со страницы Releases.

## 1. Меню F1 — Dark Tokyo, генеративная текстура + анимации

- **F1** — переключатель: открыло с анимацией, закрыло с анимацией.
  Повторное нажатие в середине — плавный разворот направления. По умолчанию
  **закрыто**.
- Геометрия: слева, **21% ширины × 100% высоты** экрана, пересчитывается от
  физического размера окна при каждом открытии.
- **Текстура** (генеративная, без UI-элементов — «чистый холст»): вертикальный
  градиент `#252a40 → #15161f`, свечение неоновой кромки `#7aa2f7` по правому
  краю, мягкое угловое сияние `#bb9af7` сверху справа, альфа 255 → 71 к правому
  краю — сквозь панель просвечивает фон. Поверх текстуры — два спрайта-полосы
  (векторная чёткость на любом DPI): неоновая кромка `#7aa2f7` (α 0.92) и
  внутренний разделитель `#bb9af7` (α 0.75).
- **Анимация** (250 мс, smoothstep): панель выезжает из-за левого края
  (сдвиг (1−s)·1.05·mw) и проявляется (α = s·0.86), полосы следуют за краем
  панели. Завершение открытия — точное (p==1.0), закрытие — despawn трёх
  сущностей + 250 мс дренаж пайплайна, затем камера деспавнится и приложение
  засыпает (0% CPU).
- **Устойчивость к «залипанию» клавиши**: тренировочный/тестовый автопресс
  делает `release` + `press` — `ButtonInput::press` игнорирует just_pressed,
  если клавиша уже в нажатом наборе (обнаружено E2E-трейсом).
- Изменение размера окна закрывает меню мгновенно (без анимации) — геометрия
  всегда пересчитывается при следующем открытии.

## 2. Ассеты

### 000.ktx2 — фон 15360×8640 (без изменений с v4)

- UASTC 4x4 (8 бит/тексель), `vkFormat=0`, DFD colorModel=166, sRGB, BT.709;
  суперкомпрессия Zstd по каждому мипу (scheme 2).
- Мип-цепочка 15360×8640 → 1×1, все уровни кратны блоку 4×4; RDO=0.5:
  48.82 dB UASTC / 47.61 dB после BC7-транскода при 3.25 байт/пиксель.
- **55 671 814 байт (53.09 МиБ)**, `ktx2check` — 0 ошибок. Зашит в бинарь
  через `include_bytes!`.

### menu.ktx2 — текстура меню 768×2048 (новое в v8)

- Сгенерирована (AI-основа + детерминированные слои: crop 0.375, blur 2.5,
  градиентный бленд 38%, edge-glow (tx>0.82)², corner-glow exp, левый край
  ×0.55..1, альфа smoothstep от tx=0.62 до 71).
- basisu v2.50: `-ktx2 -uastc -uastc_level 4 -srgb -mipmap -mip_srgb`:
  UASTC LDR 4x4, sRGB transfer, BT.709, Has Alpha, 12 мипов (768×2048 → 1×1),
  zstd-суперкомпрессия. **782 865 байт**, 2.99 бит/тексель.
- Аспект 0.375 ≈ аспект панели на 16:9 (0.21·16/9 = 0.373) — на 16K-мониторе
  (15360×8640, панель 3226×8640) текстура ложится почти 1:1 без интерполяции;
  на меньших экранах выборка идёт по мипам (тот же `ImageSampler::linear()`).

Обе текстуры декодируются в фоновом потоке (`std::thread` до создания App):
000.ktx2 → menu.ktx2 последовательно (минимум пиковой памяти), результат —
кортеж `(Image, Image)` через mpsc. Ошибка любой из них → `arxumbra: {e}` в
stderr + `AppExit::error()`.

## 3. CI: что делает workflow `.github/workflows/release.yml`

Публикация (содержимое этого каталога = корень репозитория; бинарь в git
**не входит** — `.gitignore`, лимит GitHub 100 МБ на файл):

```
unzip arxumbra-v8.zip && cd arxumbra-v8
git init -b main && git add -A && git commit -m "ArxUmbra v8"
git remote add origin git@github.com:<ваш-логин>/arxumbra.git
git push -u origin main
git tag v8.0.0 && git push origin v8.0.0    # <- запускает CI и создаёт Release
```

Проверка перед push: `git ls-files | wc -l` → **12 файлов** (сам бинарь
остаётся рядом на диске, но в git не попадает).

### Если CI упал на шаге Preflight / train-exit.patch

Значит, репозиторий загружен не полностью. Типичные причины:

- **Веб-загрузка файлов на github.com** («Add file → Upload files») — не годится:
  лимит 25 МБ на файл (assets/000.ktx2 весит 55 МБ) и легко потерять скрытые
  каталоги `.cargo/`, `.github/`. Заливайте только через git-клиент.
- Частичная распаковка архива. Распакуйте заново и сравните: в корне архива
  12 позиций (5 каталогов + 6 файлов репозитория + бинарь `.xz`),
  `git ls-files | wc -l` = 12.
- Старый неполный коммит в истории: скопируйте полное дерево поверх и сделайте
  новый коммит (`cp -r arxumbra-v8/. ваш-репозиторий/ && git add -A`).

Preflight-шаг CI проверяет все 12 обязательных файлов до начала сборки и
печатает, чего именно не хватает.

Триггеры: push тега `v*` (создаёт Release) или ручной запуск из вкладки Actions
(только артефакты). Порядок жёсткий: `needs:`-цепочка linux → macos → windows →
release.

| # | job | раннер | конвейер |
|---|-----|--------|----------|
| 1 | `linux` | ubuntu-24.04 | weston+lavapipe+wayland-dev → 3 сборки + 4 тренировки (с автонажатием F1) → PGO+FAT LTO+BOLT aggressive → strip → smoke |
| 2 | `macos` | macos-14 (M1) | PGO-инструментирование → 2 прогона (best-effort) → PGO+FAT LTO → strip |
| 3 | `windows` | windows-latest (MSVC) | PGO → 2 прогона через WARP DX12 (best-effort) → PGO+FAT LTO |
| 4 | `release` | ubuntu-latest | 3 артефакта + `SHA256SUMS.txt` → GitHub Release |

Особенности: тренировочный патч `tools/train-exit.patch` — самовыход через 75 c
**и два автонажатия F1** (t=30 c открыть, t=48 c закрыть) — профили пишутся и на
пути меню; `.gitattributes` (`* -text`) против CRLF-поломки `git apply` на
Windows; BOLT на ubuntu ставится как `bolt-18` c симлинками
`llvm-bolt`/`merge-fdata`/`libbolt_rt_instr.a`; tar.gz-артефакты сохраняют
exec-бит.

**Linux-зависимости сборки** (исправлено в v8 — без этого wayland-sys падает на
pkg-config): `libwayland-dev libxkbcommon-dev pkg-config` + `weston
mesa-vulkan-drivers` (тренировки) + `bolt-18` (Ubuntu 24.04) / `llvm-bolt`
(Debian).

## 4. Рантайм — одна функция `main`, 15 параметров системы

- Пайплайн-декод (фоновый поток + mpsc + невидимое окно до готовности текстур),
  анти-SIGILL флаги, реактивный сон (0% CPU), Mailbox + frame_latency 1,
  mimalloc, `#![deny(warnings)]` + `#![forbid(unsafe_code)]` — всё как в v7.
- Система `Update` осталась на **15 SystemParam** (лимит Bevy — 16; один
  слот зарезервирован под тренировочный патч, добавляющий `tm`-таймер).
- Состояние меню — один `Local`-кортеж `ma: (p, last_frame, dir, sleep_at)`:
  анимация считается по `Instant`-дельтам (без `Res<Time>` — экономия
  параметра), завершение проверяется **по направлению** (`dir>0 && p==1.0` /
  `dir<0 && p==0.0`) — защита от float-ULP-края: на первом кадре закрытия
  `1.0f32 − dt/0.25` может быть тождественно `1.0f32`, и без этой проверки
  анимация умирала на старте (поймано E2E-трейсом, p=0.999999 в логе).
- Обновление спрайтов — `Commands::insert((Sprite, Transform))` на трёх
  сущностях: пока меню в покое (dir==0), анимационный блок не выполняется
  вообще — steady-state стоимость нулевая.

## 5. Сборка: трёхстадийный конвейер через cargo-pgo

```
git apply tools/train-exit.patch

cargo pgo build -- --locked
export XDG_RUNTIME_DIR=... WAYLAND_DISPLAY=arx-wayland VK_ICD_FILENAMES=... WGPU_BACKEND=vulkan
export LLVM_PROFILE_FILE=target/pgo-profiles/train_%m_%p.profraw
timeout 240 ./target/x86_64-unknown-linux-gnu/release/linux-subsystem-for-arxumbra   # x2

cargo pgo bolt build --with-pgo -- --locked
timeout 240 ./target/x86_64-unknown-linux-gnu/release/linux-subsystem-for-arxumbra-bolt-instrumented   # x2

git checkout -- src/main.rs
cargo pgo bolt optimize --with-pgo \
  --bolt-args='-reorder-blocks=ext-tsp -reorder-functions=hfsort+ -split-functions -split-all-cold -icf=1 -jump-tables=aggressive -peepholes=all -sctc-mode=heuristic -dyno-stats' \
  -- --locked
strip target/x86_64-unknown-linux-gnu/release/linux-subsystem-for-arxumbra-bolt-optimized
```

Детали конвейера — как в v7 (cargo-pgo добавляет `--release` и `--target`
сам, cargo-аргументы типа `--locked` — только после `--`; профили пишутся
только при чистом exit; `strip = "none"` в профиле, стрип — последний шаг;
FAT-LTO линк ест ~10 ГБ памяти).

## 6. Валидация v8 (weston headless + lavapipe, E2E-трейс WAYLAND_DEBUG)

Функциональный прогон с автонажатиями F1 (opt-1 quick-сборка, маркеры в
stderr):

```
open → anim(dt=0.000, p=0.000, dir=1) → anim(dt=0.006) → anim(dt=0.219, p=0.897)
     → opened (p==1.0, dir=0)
close → f1toggle(p=1, dir 0→-1) → anim(dt=0.000, p=0.999999)  <- float-ULP кадр
      → anim(dt=0.246, p=0.016) → anim(dt=0.234, p=0.000, dir=0) → closed → slept
reopen (из desktop_app: камера деспавннута!) → anim → opened
close2 → anim → closed → slept → exit=0 (AppExit::Success)
```

Полный цикл: открытие/закрытие/повторное открытие из спящего режима, чистый
выход, ноль ошибок в stderr. Smoke финального бинаря (25 c, пустой stderr)
доказывает декодирование обеих текстур — ошибка любой ушла бы в stderr через
`arxumbra: {e}`.

## 7. Управление

- **F1** — открыть/закрыть боковое меню (анимация 250 мс, повторное нажатие
  разворачивает направление).
- **Esc (удержание 7 секунд)** — выход. Другого ввода нет.
